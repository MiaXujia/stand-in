# 会话管理设计提案

## 目标

每次点击“新建对话”进入一段空白会话；左侧可以新建、选择并继续旧会话。不同会话的消息列表和模型短期上下文互不混用。人格卡与经允许的长期记忆仍由整个应用共用。

## 已有结构与问题

- 当前 `messages` 和 `turns` 没有 `session_id`。
- `GET /api/messages` 返回全局消息；`ReplyService.reply()` 将全局最近 12 条放进模型上下文。
- React `useChat` 只有一份消息状态和一个待完成回合。因此只做前端会话列表会造成记录与模型上下文串会话。
- 当前本机的 20 条旧演示消息已备份并清除。本提案仍需兼容其他已有数据库中的真实历史。

## 方案比较

1. **仅前端用 localStorage 分组：不采用。** 多设备不会同步，服务端仍会把全部消息用于回复。
2. **前后端都按会话隔离：采用。** 与用户看到的列表一致，回复上下文也正确，支持后续导出与删除。
3. **每个会话独立数据库：不采用。** 迁移、备份、后台查看和主动消息路由都会复杂化。

## 用户行为

- 桌面左栏：品牌、醒目的“新建对话”按钮、按最近活动排序的会话列表；当前项有文字和背景双重选中状态。
- 手机：顶栏按钮打开同一列表的抽屉；选中后关闭抽屉并进入该会话。
- 首次进入：若没有会话，显示空白欢迎页；点击输入框发首条消息时建立第一段会话。
- 点击“新建对话”：立即进入空白草稿；只有首条消息发送成功才在服务端建立记录，避免空会话堆积。当前会话未发送过消息时重复点击仍停留在同一草稿。
- 新会话初名取首条用户消息的前 18 个字符；可以截断显示但保留完整标题。后续可加重命名与删除，本轮不扩展。
- 最近选中的会话写入 URL 查询参数 `?session=<id>`，刷新与分享同一设备链接时能回到它；无效 ID 回到最新会话并提示。
- 新会话只清空这段对话的短期消息；人格、长期记忆、披露说明继续有效。切回旧会话可见其原记录。

## 数据与迁移

- 新增 `sessions(id TEXT PRIMARY KEY, title TEXT, created_at TEXT, updated_at TEXT)`。
- `messages`、`turns` 新增 `session_id`；新写入的消息与回合必须带该字段。会话内查询按 `session_id` 过滤，增量游标继续使用消息 ID。
- 迁移已有数据库时，把旧消息和关联回合放进一段“历史对话”，不丢数据；空数据库不创建假会话。
- `client_msg_id` 继续全局唯一。重试时同时核对原回合的 `session_id`，禁止同一 ID 跨会话复用。
- 定时主动消息放进一个独立的“日常来信”会话，避免突然出现在用户刚新建的空白对话里；已有主动消息随历史迁移。
- 所有会话仍受现有 `sid` Cookie 保护；当前产品仍是单个聊天身份，不引入多用户系统。

## API

- `GET /api/sessions`：按 `updated_at DESC` 返回 `id/title/updated_at/last_message_preview`。
- `POST /api/sessions`：创建会话；由第一条消息触发，可接受客户端生成的幂等 ID。
- `GET /api/sessions/{id}/messages?after_id=...`：只返回该会话消息。
- `POST /api/sessions/{id}/chat` 与 `/chat/stream`：在该会话创建回合并生成回复；原 SSE 事件格式保持一致。
- `GET /api/turns/by-client/{client_msg_id}`：返回 `session_id` 供断流恢复时校验。
- 原全局 `/api/messages`、`/api/chat` 可在迁移期保留兼容层，但新前端只调用会话接口；以后再移除。

## 前端状态

- `useSessions` 管列表、新建草稿、选中与 URL 同步。
- `useChat(sessionId)` 管当前会话消息、SSE、轮询、重试。切换会话时终止前端播放，并按 `session_id + client_msg_id` 在后台核对已提交回合，保证回复不会落到别的会话。
- 左栏列表轮询或在发送成功后更新排序；空会话标题与加载、错误状态都有明确反馈。
- 保持现有藕荷色设计、披露提示、设置抽屉和无消息欢迎页。

## 验收重点

1. A、B 会话互不显示消息；A 的提问不会作为 B 的模型短期历史。
2. 新建草稿为空，刷新可恢复已保存会话；连续点击新建不产生空记录。
3. A 发送中切到 B，A 的 SSE 不会渲染到 B；返回 A 后可恢复最终提交结果。
4. 旧库迁移后历史只出现在“历史对话”；空库不会出现示例记录。
5. 手机抽屉、键盘导航、选中状态和窄屏布局可用。

## 待确认的产品决定

建议主动消息进入独立“日常来信”会话。若希望它接在最近一段聊天后面，改动仅涉及主动消息的会话选择规则。
